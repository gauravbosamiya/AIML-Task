# Feature Extraction
- Now coming to the feature extracting part we are using Transfer Learning to extract feature from the image because Dataset is small. Building CNN from scratch will cause to overfitting/underfitting problem. 
- Using MobileNetV2 we are extracting features from the images. I am using MobileNetV2 because it is lightweight and works well when we have less data. 
- Also I have used image augmentation because it helps the model to understand a variety of images

# Model Building 
- I am using XGBoost for final prediction because we have small data and XGBoost works well with extracted features + tabular data. 
- our feature vector is 1281-dim and XGBoost handles high dim well.  


# Model Training
Since qty value is not stable so i applied log1p transformation on the target variable to stabilize training.
And I am using GroupKFold cross validation (n_splits=5) to handle overfitting.

2. How does your prediction system work? (logic/model)

the prediction system is a multimodal pipeline it takes two inputs (design image + rate) and predicts the expected sales quantity (qty).

Step 1 - Image goes into MobileNetV2

The design image is resized to 224×224 and passed through MobileNetV2 (pretrained on ImageNet)
MobileNetV2 extracts visual patterns from the image — shape, color, texture, design style
Output is a 1280-dimensional feature vector representing the image

Step 2 — Rate normalization

The rate (price) is normalized by dividing by rate_max from training data
This converts it to a value between 0 and 1
Output is a 1-dimensional value

Step 3 — Feature concatenated

Both vectors are concatenated together
[1280 image features] + [1 rate feature] = 1281-dimensional input vector

Step 4 — XGBoost predicts

the 1281-dim vector is pass into the trained XGBoost model
XGBoost learned during training which image patterns + price combinations lead to high or low demand
output is a log-scaled qty prediction

Step 5 — Reverse log transformation

during training, qty was transformed using log1p to handle values
so at prediction time we reverse it using expm1 to get the actual qty
final output is rounded to the nearest integer
